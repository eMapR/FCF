# FCF — Bayesian Spatial Carbon Modeling Application

FCF is an R-based application for producing spatial estimates of forest carbon and associated uncertainty.

The application is designed to be used through a graphical user interface (GUI). You do not need to modify the underlying R scripts to run a standard analysis.

This guide walks through the application from a user's perspective: getting started, understanding the interface, running the workflow, and understanding the results.

------

## Getting Started

A typical FCF analysis follows four steps:

1. **Check Inputs** — Make sure the required files are present and spatially compatible.
2. **Fit Variogram** — Examine spatial patterns in the plot data.
3. **Fit Spatial Model** — Fit the Bayesian spatial carbon model.
4. **Predict Outputs** — Generate spatial carbon predictions and uncertainty estimates.

These steps are run directly from the Run Workflow panel in the application.

For a normal analysis, run the steps in order from Step 0 through Step 3.

## Understanding the Interface

The FCF interface is divided into several panels. Each panel has a specific purpose.

### Console Output Panel

The Console Output panel displays messages produced by the application while a workflow step is running.

Use this panel to follow the progress of an analysis and determine whether a step completed successfully.

If something goes wrong, this is the first place to look. Errors, missing files, configuration problems, and other messages are displayed here.

When Step 0 is run, for example, the console reports whether the application can find the configured data directory, site directory, boundary, plot data, carbon raster, and output directory.

### Plot Preview Panel

The Plot Preview panel displays diagnostic plots and results generated by the workflow.

The panel updates automatically as steps finish.

**After Step 1 — Variogram**

The preview displays the empirical semivariogram generated from the residuals of the initial regression model.

This plot helps show whether spatial structure remains in the data and how that spatial relationship changes with distance.

**After Step 2 — Model Diagnostics**

The preview displays diagnostic plots from the Bayesian model.

The figure contains trace and density plots for three model parameters:

- `phi` — spatial decay
- `sigma.sq` — spatial variance
- `tau.sq` — nugget or error variance

The trace plots help determine whether the model is sampling consistently rather than drifting or becoming stuck.

The density plots show the estimated posterior distribution of each parameter.

**After Step 3 — Predictions**

The preview displays the spatial prediction results.

The final display contains:

- **Mean prediction map** — the estimated carbon value across the landscape.
- **Uncertainty map** — the standard deviation associated with those predictions.

The full prediction rasters are also saved to the configured output directory.

### Quick Config Shortcuts Panel

The Quick Config Shortcuts panel provides easy access to the settings that users are most likely to change between analyses.

For most routine runs, these settings may be all that you need to modify.

**Site**

The name of the site being analyzed.

This must correspond to a site folder located inside the selected Data Dir.

**Data Dir**

The parent directory containing the input data for your sites.

Use Browse to select the directory instead of typing the complete path manually.

**Output Dir**

The directory where FCF will save model results, plots, prediction rasters, and other output files.

Use Browse to select the desired directory.

**Apply To YAML**

Copies the Site, Data Dir, and Output Dir values shown in the shortcut panel into the full YAML configuration.

Use this after changing values in the Quick Config Shortcuts panel.

**Pull From YAML**

Updates the shortcut fields using the values currently stored in the YAML Editor.

This is useful if you edited these settings directly in the YAML configuration.

### YAML Editor Panel

The YAML Editor contains the complete configuration used by the modeling workflow.

While the Quick Config Shortcuts panel exposes the most commonly changed settings, the YAML Editor provides access to all model settings.

Most users should begin with the default or example configuration and only modify advanced parameters when necessary.

The buttons below the editor provide several options:

**Load YAML** — Open an existing YAML configuration file.

**Load Template** — Load the example configuration as a starting point.

**Save** — Save changes to the currently loaded configuration file.

**Save As** — Save the configuration as a new file.

Using Save As is useful when experimenting with different model settings because it allows you to preserve the original configuration.

### Run Workflow Panel

The Run Workflow panel is where the analysis is performed.

The workflow consists of four steps. Each step depends on the results of the previous step, so they should normally be run in order.

The status next to each step indicates whether it is:

- Pending
- Running
- Complete
- Failed

**Step 0: Check Inputs**

Start every new analysis with Step 0: Check Inputs.

This step checks that FCF can find and use the data required for the analysis.

It checks:

- Configuration settings
- Input file locations
- Site directory structure
- Boundary data
- Plot data
- Carbon raster
- Coordinate reference systems
- Raster coverage

Watch the Console Output panel while Step 0 runs.

If something is missing or incompatible, the console will report the problem.

Resolve any errors before continuing to Step 1.

**Step 1: Fit Variogram**

Step 1 fits an initial non-spatial regression model and examines spatial structure in the residuals.

When the step finishes, examine the Plot Preview panel.

The semivariogram displayed here is used to help characterize the spatial relationship in the data and inform the spatial model used in Step 2.

**Step 2: Fit Spatial Model**

Step 2 fits the Bayesian spatial model using MCMC sampling.

This step can take substantially longer than Steps 0 and 1.

When it finishes, examine the diagnostic plots in the Plot Preview panel.

These plots provide information about the behavior of the model and should be reviewed before proceeding to the final predictions.

**Step 3: Predict Outputs**

Step 3 applies the fitted model across the analysis area.

This produces the final spatial carbon predictions and their associated uncertainty.

Prediction files are written to the configured Output Dir, and the resulting prediction and uncertainty maps are displayed in the Plot Preview panel.

**Allow Out-of-Order Runs**

Normally, FCF prevents a step from being run until the previous step has completed.

The Allow out-of-order runs option overrides this behavior.

Most users should leave this option unchecked.

It can be useful when reopening an existing analysis where the required outputs from earlier steps have already been created.

### Help Panel

The Help panel provides a quick reference for the FCF interface.

It contains descriptions of the major panels, workflow controls, configuration options, and diagnostic displays.

Use this panel when you need a reminder about what a particular part of the interface does without leaving the application.

## Running an Analysis

For a typical analysis, use the following workflow.

### 1. Select your data

Open Quick Config Shortcuts and set:

- Site
- Data Dir
- Output Dir

Click Apply To YAML.

### 2. Check your inputs

Run Step 0: Check Inputs.

Watch the Console Output panel.

Do not continue until the required files are found and the spatial-data checks complete successfully.

### 3. Examine spatial structure

Run Step 1: Fit Variogram.

When it finishes, examine the semivariogram in the Plot Preview panel.

### 4. Fit the spatial model

Run Step 2: Fit Spatial Model.

This may take considerably longer than the previous steps.

When it finishes, examine the trace and density plots in Plot Preview.

### 5. Generate predictions

Run Step 3: Predict Outputs.

When the process finishes, examine the prediction and uncertainty maps and locate the complete output files in your Output Dir.

## Input Data

Each analysis site requires three primary spatial inputs.

### Boundary

A polygon defining the area where predictions will be generated.

Expected location:

```
<site>/bnd/bnd.shp
```

### Plot Data

A point shapefile containing field measurements used to fit the model.

Expected location:

```
<site>/plots/plots.shp
```

The plot data must contain a field named `Total.Carb`. This field contains the measured carbon value used by the model.

### Carbon Raster

A single-band raster containing the predictor variable used to model carbon.

Expected location:

```
<site>/carbon-map.tif
```

### Spatial Compatibility

The boundary, plot data, and raster should use the same coordinate reference system.

The raster must also cover the analysis boundary.

Step 0 checks these requirements before the modeling workflow begins.

## Understanding the Outputs

FCF creates several files during an analysis. Not every file needs to be used directly by the user.

The most important outputs are described below.

### `semivariogram.png`

Created during Step 1.

This is the diagnostic variogram displayed in the Plot Preview panel.

It shows the spatial structure identified in the residuals of the initial model.

### `chainImg.png`

Created during Step 2.

This contains the MCMC diagnostic plots displayed in the Plot Preview panel.

Use these plots to evaluate the behavior of the Bayesian model.

### `pred.tif`

Created during Step 3.

This is the primary raster product for viewing and mapping the model predictions.

It contains the predicted mean carbon values and associated per-pixel uncertainty.

Use this product when you want to visualize carbon estimates across the landscape or examine individual pixel predictions.

### `pred-joint.tif`

Also created during Step 3.

This prediction product preserves information needed for uncertainty-aware aggregation.

Use the joint prediction when estimating uncertainty for quantities summarized across an area, such as:

- Mean carbon within a management unit
- Carbon totals within a polygon
- Other area-based summaries where uncertainty needs to be reported

In simple terms:

Use `pred.tif` for mapping and examining individual predictions.

Use `pred-joint.tif` when aggregating predictions across an area and carrying uncertainty into that calculation.

### Model Files

FCF also saves files such as:

- `m.1.RData`
- `m.1.pred.RData`
- `m.1.pred.joint.RData`

These contain fitted model objects and predictive samples used by the workflow.

Most users will not need to interact with these files directly, but they are retained so analyses can be reproduced or examined in greater detail.

## Troubleshooting

**A step fails**

Look at the Console Output panel first.

The final messages usually indicate what caused the problem.

**Step 0 reports a missing file**

Check:

- Site
- Data Dir
- Input folder structure
- File names

Make sure the selected Site actually exists inside Data Dir.

**Step 0 reports a CRS problem**

Make sure the boundary, plots, and carbon raster use compatible coordinate reference systems.

**A later workflow step is disabled**

FCF normally requires the workflow to be completed in order.

Complete the previous step first.

If you intentionally want to use outputs from an earlier analysis, Allow out-of-order runs can override this restriction.

**Nothing appears in Plot Preview**

Step 0 does not produce the same diagnostic plots as the later modeling steps.

After completing Steps 1–3, the Plot Preview should update automatically when a diagnostic image is generated.

**Step 2 is taking a long time**

This can be normal.

The Bayesian spatial model uses MCMC sampling and can take considerably longer than the initial input and variogram steps.

Large analyses or configurations with many samples may require substantially more processing time.

## Installation

FCF requires R and the following R packages:

- `yaml`
- `terra`
- `geoR`
- `spBayes`

A working Tcl/Tk installation is also required for the graphical interface.

Install the required R packages with:

```
Rscript -e "install.packages(c('yaml','terra','geoR','spBayes'), repos='https://cloud.r-project.org')"
```

From the repository directory, launch FCF with:

```
Rscript src/gui.R
```

On Windows, the GUI can also be launched from an R console with:

```r
source("src/gui.R")
```

For most users, the GUI is the only interface needed to run FCF.

## Advanced Configuration

Most routine analyses can be performed using the Quick Config Shortcuts and the default YAML settings.

The YAML configuration also exposes advanced model settings, including:

- Number of MCMC samples
- Thinning
- Spatial-model priors
- Tuning parameters
- Raster coverage behavior

These settings affect how the statistical model is fit and generally should not be changed unless you understand their effect on the analysis.

Two raster coverage settings are available:

**`strict.raster.coverage`**

Controls whether the workflow stops when the raster does not completely cover the analysis boundary.

**`raster.coverage.tolerance`**

Allows a small difference between the raster and boundary extents, which can be useful for minor discrepancies caused by pixel alignment or rounding.

## Repository Contents

The main application files are located in `src/`.

- `gui.R` — Launches the graphical interface.
- `step0.R` — Checks and prepares input data.
- `step1.R` — Fits the initial model and variogram.
- `step2.R` — Fits the Bayesian spatial model.
- `step3.R` — Generates spatial predictions.
- `mod.R` — Contains shared modeling and utility functions.
- `config.yaml` — Contains the default application configuration.
- `config_example.yaml` — Provides an example configuration that can be used as a starting point.
